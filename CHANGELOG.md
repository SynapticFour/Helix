## Unreleased

- Open-source quality review before announcement (`docs/OPEN_SOURCE_RELEASE_CHECKLIST.md`): LICENSE/SECURITY/CONTRIBUTING present; **no** CODE_OF_CONDUCT, issue templates, tags, or release workflow. `Cargo.lock` exists but `docs/DEPENDENCY.md` is stale. Report only — do not tag or publish from that review.
- Lightweight verification-run identity so two `helix verify` JSON files can be compared (`docs/RUN_IDENTITY.md`, `src/run_identity.rs`): Helix version, HelixTest pin, profile, test ids, target, `fixture_version` (`helix-fixtures-v1`), schema version, timestamp, and (bench only) workload id/version. `helix compare` copies those into `previous_identity` / `current_identity` and sets `same_measurement` / `suite_changed`. Identity mismatch is not `NEW_FAIL`. Not a signed audit trail. Not scientific reproducibility. Not HELIOS (no signature, RO-Crate, PDF). Distinction: [docs/HELIX_VS_HELIOS.md](docs/HELIX_VS_HELIOS.md) §3.
- Evaluator path (`docs/EVALUATOR_JOURNEY.md`, rewritten `docs/FOR-EVALUATORS.md`): sibling HelixTest pin, `make prove`, **`make verify-fixture`** (`examples/verify_fixture.rs`) so `helix verify` runs against the in-process DRS mock without Ferrum. Stale “not yet a runnable suite” text is gone. `scripts/require-helixtest.sh` explains a missing sibling. CI and pre-commit run verify-fixture after prove. Default `RUST_LOG=error` so HelixTest DEBUG traces do not hide `HELIX VERIFICATION`. Report failures via GitHub Issues.
- Implementation-neutral external target contract (`docs/EXTERNAL_TARGET_CONTRACT.md`): `helix verify <url>` against documented GA4GH DRS/WES HTTP plus explicit fixtures. No Ferrum, Synaptic Four config, HelixTest internals, special headers, or private APIs. Standard / fixture / optional are separated. The contract is not stricter than the GA4GH specs; pin v0.1.3 runner extras are listed separately.
- External evaluator pack (`docs/evaluator-pack/`): install, one-page explanation, target and fixture requirements, commands, example `VerificationRun` JSON, interpretation, failure-report template. No sales CTA, Synaptic Four account, Helix Cloud, or telemetry.
- Local adversarial HTTP fixtures (`docs/FIXTURES.md` §16, `tests/support/mock_adversarial.rs`): malformed / huge JSON, invalid headers, redirects, slow responses, connection close, wrong content-type, 418, malformed service-info, long strings. In-process only. Helix must terminate, honor timeouts, not panic, not leak decoy tokens, and must not treat malformed responses as overall PASS.
- Helix-as-a-client threat model (`docs/THREAT_MODEL.md`): operator-chosen untrusted HTTP target. Helix-owned client does not follow redirects, caps response bodies (2 MiB), rejects URL userinfo, and redacts Authorization / Bearer / JWT / HMAC values from stdout, stderr, JSON, and diagnostics. Not a security product. HelixTest `access_url` fetch remains a documented residual. Dummy fixtures only.
- Frozen `helix verify` JSON schema (`schemas/helix-verification-v1.json`, `docs/SCHEMA.md`): `schema_version` `helix-verification-v1`, services as `discovery`, checks as `executed`/`skipped`, status `pass`/`fail`/`skip`/`error`, failure + diagnostic. CI validates generated JSON. Not HELIOS evidence. Not a `services`/`passed` OverallReport.
- Human verification report (`docs/REPORT.md`, `format_verify_text`): `HELIX VERIFICATION` answers what / against / Helix version / HelixTest pin / services / results / why / summary. JSON `VerificationRun` is the same facts. `Changes:` on a single run is **Not compared** (`helix compare`). Not a PDF, not RO-Crate, not certification.
- Deterministic verification diagnostics (`docs/DIAGNOSTICS.md`, `src/diagnostics.rs`): fail/error rows for DRS `HLX-DRS-001`–`005` and WES `HLX-WES-001`–`008` may include `diagnostic` (code, id, expected, observed, likely category, hint, **possible causes**). Not an AI diagnosis. Not a root-cause claim. Unparsed failure text is “not determined”, never an invented HTTP status. Pass/skip/TES/TRS/auth/bench have none. A bench warning is still not a verification failure.
- Security Behavior Profile (`docs/SECURITY_PROFILE.md`, `src/security/profile.rs`): five HTTP invariants (`HLX-AUTH-010`–`014`) with request, acceptable status class, failure code, severity, and dummy HMAC fixture. Negative `VerifierPolicy` mocks prove Helix detects broken gates. Dummy secrets only.
- Crypt4GH protocol layout after that profile (`docs/CRYPT4GH.md`, `HLX-AUTH-050` / `053` / `054`): well-formed envelope, invalid envelope rejected, HTTP envelope-or-skip. No `crypt4gh` crate, no private keys, no KMS. A pass is not “secure”. HelixTest’s secret-key rewrap path stays unwired (`HLX-AUTH-051`–`052` reserved).
- Verification regression at stable Helix `id` (`docs/REGRESSION.md`, `src/compare.rs`, `helix compare`): PASS→FAIL is `NEW_FAIL` (exit 1). Fail→fail is `UNCHANGED_FAIL`, not a new regression. SKIP→PASS is `FIXED_SKIP`, never a silent pass. Not a score drop. Text + JSON.
- helix-action (sibling) compares `VerificationRun` at that id (`helix compare` / mirroring classifier). PR comment leads with new regressions / fixed / existing failures, not an X/Y score. Job may fail on `NEW_FAIL` or runtime errors only. Not a required Ferrum `main` check.
- Repeatable `helix bench` engine ([docs/BENCHMARKS.md](docs/BENCHMARKS.md)): workload `http.drs.smoke.v1`, warmup/repetitions, distribution compare (median / p95 where available / error-rate / optional RSS). Measurement, warning, and regression are separate. A warning means performance changed enough to merit human inspection; it does not mean the implementation is incorrect. Never a verification failure. Thresholds do not fail CI. Not a significance test. Not GIAB.

- Deterministic fixture catalog (`docs/FIXTURES.md`): in-process mock DRS/WES, known-invalid responses, dummy HMAC/Crypt4GH. `make prove` is docs + `cargo test --locked` with no Ferrum/Docker/credentials. Live verify is opt-in `make test-live`. No real secrets. Fixture tests are not ignored.
- Helix verify profiles (`docs/PROFILES.md`, `src/profile.rs`): declarative `generic` (default) and `ferrum`. Profiles set expected/enabled services, optional checks, fixtures, and HelixTest `Features`. Execution stays `Mode::Generic` on public HTTP. Ferrum is never selected from WES `name`. `--profile` is additive; unknown values exit 2. JSON `profile` is `generic` or `ferrum`.
- Public CLI contract frozen (`docs/CLI_CONTRACT.md`): `helix verify` text/json argv, exit 0/1/2, stdout JSON vs stderr logs, skip and discovery semantics, version fields. JSON must not include human-only formatting. TES/TRS/htsget command namespaces reserved, not implemented.
- DRS is a first-class Helix verification profile (`helix verify`, `docs/DRS_PROFILE.md`): discover → testable → HelixTest adapter → Helix `VerificationRun` JSON (target, Helix/HelixTest versions, stable ids/codes, executed/skipped, failure codes). Skip-only and unreachable are not passes. DETECTED is not a pass. D3 revisit: verify JSON is no longer HelixTest `OverallReport`; `helix security` is unchanged.
- HelixTest adapter boundary (`src/adapter`, `docs/HELIXTEST_ADAPTER.md`): pinned HelixTest DRS runs behind `HelixTestAdapter`; results translate to Helix `VerificationResult` (identity preserved, SKIP never PASS, errors kept, pin `v0.1.3` / SHA recorded). HelixTest stays its own git root. Ferrum is not imported.
- Discovery states `NOT_DETECTED` / `DETECTED` / `TESTABLE` (`docs/DISCOVERY.md`). CLI never prints `found` as verified. DETECTED is not a pass. Only DRS is TESTABLE in `helix verify` today. Lightweight probes; versions only from service-info JSON.
- Stable test identity catalog (`src/identity.rs`, `docs/TEST_IDENTITY.md`): Helix `id`/`code`/`name`/`service`/`category`/`severity` with reserved `HLX-DRS|WES|TES|TRS|HTSGET|BEACON|AUTH|BENCH|DISCOVERY` ranges. HelixTest names are not renamed; wraps map Helix ID → exact HelixTest string. Changing an assigned id or code is a compatibility change.
- Helix-native verification domain model (`src/model.rs`, `docs/VERIFICATION_MODEL.md`): `VerificationRun` with PASS/FAIL/SKIP/ERROR, stable check ids (`drs.object.not_found` / `HLX-DRS-005`). Skip is never pass. Not HELIOS, not a compliance score.
